# Require scoped proof-first assurance

## Status

Accepted.
Supersedes the universal completion rule in [0002](0002-mandatory-source-bound-proofs.md), while preserving the bounded workload boundaries in [0003](0003-permit-proof-only-cloud-bootstrap.md) and [0004](0004-keep-assurance-directed-at-decryption.md).

## Context

The universal proof gate combined local implementation contracts with an unregistered whole-search completeness requirement.
It could not pass even after every registered local lemma succeeded, and a language-ranked cap cannot retain every true candidate.
The owner requires proofs wherever meaningful and feasible, with justified mandatory alternatives at actual semantic or empirical boundaries.
The objective remains useful, correct implementation and honest interpretation of search results.

## Decision

Require every registered native proof except the explicitly exploratory four-edge propagation model, plus the Lean theorems and the checked [assurance assessment](../../proofs/assurance.json).
Prove reciprocal settlement directly on the production body for all assignment states and an arbitrary array index.
These proofs establish partial failure, exact queue growth, assignment bits and pointwise framing without claiming that the separate compositional function contract was checked.
Remove the exploratory model's unverified settlement stub.

Require the assessment to cover every whole-search boundary, retain relevant native core proofs, explain its limits and reconsideration condition, and validate current full hardware recovery with matched controls.
Reject missing or duplicate scopes, unknown classifications, empty reasons, unsupported whole-search claims and dependence on exploratory proofs.
A timeout alone is not a valid alternative.
The production policy predicate itself has a source-bound native proof.

`prove --verify` checks scoped completion.
`prove --verify-search` retains the stronger whole-search claim and remains unavailable until its actual contracts are proved.
Full-search cloud admission continues to use the stronger check; a scoped pass cannot authorize that workload.
Known-key verification may bootstrap through the existing narrow proof requirements, avoiding circular dependence on a recovery receipt that has not yet been produced.
Runtime-only measurements use the same bootstrap with an exact benchmark command and an optional period from one through six.
This workload cannot admit an arbitrary program, a crib batch or a reading declaration, and it does not satisfy the complete-search gate.

## Consequences

Small deterministic invariants remain mandatory proofs.
Unsupported model refinements, driver and operating-system behavior, and heuristic accuracy require explicit limited claims and completed source-bound empirical checks.
The investigation has ended without a reading; this change does not restart target searches or convert a bounded negative result into exhaustive rejection.
The generic shared skill applies the same distinction without embedding this repository's candidates or verifier choices as universal requirements.
